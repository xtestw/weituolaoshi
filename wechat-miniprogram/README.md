# 次元委托微信小程序 V1

这是从网页版业务原型拆出的微信原生小程序工程，可以直接导入微信开发者工具预览。当前版本以本地模拟数据跑通交互，真实支付、实名认证、消息、审核和结算已预留统一接口，但上线前必须接入服务端。

## 已实现

- C端：首页双列Feed、城市、搜索、日历可约、五项筛选、消息
- C端：Coser详情、公开主页分享、服装、图文介绍、边界、24小时档期
- C端：时间/时长联动、公共场所、委托前确认、成年与同性校验、订单费用
- C端：订单列表、订单状态、取消原因、48小时取消提示、完成后结算逻辑
- B端：认证拦截、闲鱼式图文发布、封面、排序、边界逐条编辑、帖子管理
- B端：工作台、接单、订单筛选、档期、收益、保证金展示
- 统一：固定自定义底栏、消息入口、明亮“日间次元市集”设计系统

## 本地运行

1. 安装最新版微信开发者工具。
2. 选择“导入项目”，目录选择本文件夹。
3. 当前 `project.config.json` 使用 `touristappid`，可直接预览多数交互。
4. 准备正式小程序后，把 `project.config.json` 的 `appid` 改为你的小程序 AppID。
5. 开发阶段可在详情设置中暂时关闭合法域名校验；生产环境必须配置业务域名。

## 演示认证

实名认证页在本地演示环境根据18位身份证格式计算成年状态和证件性别，只把脱敏结果写入本地缓存。Coser发布入口还会模拟一次异步审核和消息通知。它们都不是生产实名认证或审核服务。

- 女性证件性别可继续对当前女性Coser下单。
- 男性、未满18岁或格式错误会被阻断。
- 正式环境必须将姓名和身份证提交到服务端，由合规实名认证供应商完成核验；前端不得保存完整证件号。

## 上线前必须替换的能力

| 能力 | 当前状态 | 生产要求 |
|---|---|---|
| 微信登录 | 未接入 | `wx.login` + 服务端 `code2Session`，创建平台用户 |
| 实名认证 | 本地演示 | 服务端调用合规实名/活体供应商，只返回认证结论 |
| 图片上传 | 临时文件 | 上传至对象存储，内容安全审核通过后才公开 |
| 帖子审核 | 本地状态 | 文本/图片机审 + 管理后台人工复核 |
| 订单 | 本地缓存 | 服务端状态机、幂等、库存/档期锁和操作日志 |
| 微信支付 | 说明弹窗 | 服务端统一下单、`wx.requestPayment`、支付回调验签 |
| 资金结算 | 未接入 | 平台订单账本、退款、佣金、Coser结算与对账 |
| 消息聊天 | 本地演示 | WebSocket/云托管消息服务、敏感词和站外导流风控 |
| 地点限制 | 本地选项 | 腾讯位置服务POI分类、营业时间和风险规则校验 |
| 订阅消息 | 未接入 | 用户授权后发送接单、退款、审核、履约提醒 |
| 客服/申诉 | 说明弹窗 | 微信客服或自建工单后台 |

## 服务端接入点

统一入口位于 `services/api.js`。配置 `app.js` 的 `apiBaseUrl` 后，逐步替换页面内本地模拟逻辑。

建议最少提供以下接口：

```text
POST /v1/auth/wechat-login
POST /v1/identity/verifications
GET  /v1/services
POST /v1/services
POST /v1/uploads/presign
GET  /v1/cosers/:id/availability
POST /v1/orders/quote
POST /v1/orders
POST /v1/orders/:id/payment
POST /v1/orders/:id/confirm
POST /v1/orders/:id/cancel-requests
POST /v1/orders/:id/complete-confirmations
GET  /v1/messages/conversations
POST /v1/messages/conversations/:id/messages
```

## 关键状态约束

- 用户必须实名、年满18周岁且与Coser证件性别相同。
- 不支持过夜服务；履约时间不能跨自然日。
- 地址必须属于允许的公共场所POI。
- 24小时内的委托必须先在订单会话中由Coser确认时间。
- 用户付款后，Coser最长24小时确认；超时自动关闭并原路退款。
- 有进行中委托的帖子锁定核心信息，不能修改或删除。
- 双方确认履约完成后才进入Coser结算。
- 48小时内取消必须填写原因并进行责任协商；保证金用于Coser责任赔付，但不能只靠前端判断。
